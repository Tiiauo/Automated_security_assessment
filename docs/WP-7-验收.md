## 实现范围

- 真实 `report_writer` 进入既有模型循环；严格校验六个有内容且顺序固定的二级章节，拒绝虚构的本轮漏洞 / 路径编号，结构失败沿用修复重试和失败阻断。
- 前四章由本轮数据库快照生成，包含来源、commit、源码指纹、阶段 / 角色、漏洞五要素和有序攻击路径；模型提供风险结论与修复建议。报告注明执行过程是生成时快照，最终归档与销毁结果查看运行记录。
- 无已验证漏洞 / 无多步路径时给出明确兜底文本；未验证漏洞和路径节点提示人工复核。仅 MOCK 模式添加 `[LLM_MOCK]` 标记。
- Markdown 渲染为独立 UTF-8 HTML，关闭原始 HTML，再用既有 nh3 白名单清理；屏蔽脚本、图片和危险链接。事实字段转义，证据使用安全代码围栏，避免插入伪造章节。
- 文件保存至 `data/reports/{project_id}/report-run-{run_id}.md/.html`。先检查报告唯一约束，临时文件替换完成后再提交数据库；事务回滚清理未提交文件，失败不发布 `report_ready`。
- 查询支持 JSON / HTML / Markdown，下载支持 md / html；检查项目归属和轮次，默认只取当前轮次，不回退旧报告。下载按数字 ID 推导规范路径，忽略数据库中的文件路径，拒绝符号链接、缺失或与数据库不一致的文件；响应设置 CSP、nosniff、no-store，下载文件名经过清理。
- 报告页接入真实结果、`report_ready` 刷新、历史轮次与下载；异步请求按序号隔离，避免切换轮次时旧响应覆盖新报告。
- 本地源码在报告阶段开始前和模型返回后再次核对指纹，生成过程中发生变化也会阻止报告发布。

未新增依赖或数据库迁移；复用现有报告表、角色引擎、事件机制、MarkdownIt 与 nh3。
