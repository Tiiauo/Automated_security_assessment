# WP-5 / WP-6 实现与验收

日期：2026-10-22。基线：WP-4 已由用户确认完成验收；本轮依据 PRD v1.9 实现 WP-5 和 WP-6。

## 实现范围

WP-5：

- 项目 WebSocket 使用与 HTTP 相同的 Cookie、JWT 和数据库会话校验；检查项目归属与浏览器 Origin，连接期间继续复核权限。支持 4401 / 4403 / 4404、30 秒 ping、10 秒 pong 截止及连续两次超时断开。
- SQLAlchemy 事务提交后才发布项目、阶段、角色、聊天、日志、资源、漏洞和报告共八类业务事件；回滚不会发布。数据库仍是唯一状态源，进程内总线只保存连接队列。
- 首帧发送快照，包含阶段、角色、最近 50 条消息、最近 100 条日志、最新资源与风险计数。指定轮次固定订阅，不指定轮次跟随启动并重新发送快照；慢连接溢出时要求重连。
- 消息、日志、资源 HTTP 查询支持分页、轮次和各自筛选条件；管理端系统资源与系统日志查询已接入。
- 每个运行项目有资源采样任务，沿用启动时的采样配置。Token 更新和定时采样通过项目行锁串行，避免覆盖累计量；停止、失败和销毁时结束采样。
- 过期日志和资源按保留配置定期清理；日志在 100 ms 窗口内集中发送，保持单条协议帧兼容。前端增加日志虚拟滚动、角色/阶段过滤、历史查询和 Token 趋势。
- 断线默认重连，不再自动显示原型数据；显式 `VITE_DEMO_MODE=1` 才允许模拟实时通道。Vite 保留原始 Host，配合 WebSocket 同源校验；部署反向代理也应保留浏览器访问的 Host。

WP-6：

- 开放真实模式的 `vulnerability_verify`；保持附录 D2 / D3 校验、修复重试和失败阻断。
- 验证角色须实际执行容器命令并给出证据、步骤和代码；缺少执行记录或关键证据时降为 `unverified`，不会冒充已验证。
- 保存候选类型，按本轮 `file_path + vuln_type` 去重并合并完整证据，保留编号。证据超过 64 KB 时保留摘要和完整工作区文件引用。
- 真实验证结论写入风险、CVSS、影响、条件、证据、复现步骤、验证代码和阶段；风险等级按 CVSS 边界映射，无法评分标为 medium 并提示人工复核。
- 攻击路径只引用本项目本轮已判定且非误报的漏洞，至少两步，步骤按数组顺序连续编号。漏洞删除通过既有数据库外键级联删除关联步骤。
- 四个漏洞/路径查询接口已接入归属校验、列表筛选/分页、完整详情与历史轮次。项目详情提供整轮风险和验证状态统计。
- 页面消费漏洞与阶段通知刷新列表；验证更新不重复增加计数；路径中的未验证节点保留人工复核标识。
